# 可以講的特色與 Demo 腳本

這份給錄影片與現場說明用。收錄的每一條都附「怎麼當場驗證」，
沒有任何一條是話術。講不出驗證方式的就不要講。

紀錄日期 2026-09-12。數字如果變了，跑 `./scripts/verify-all.sh` 取最新的。

---

## 一句話

同一個規則引擎，兩個方向都走得通：檢查估價師填好的書表有沒有填錯，
以及從勘查表算出書表該填什麼。每一格都指得回官方評價基準明細表的頁碼，
而且計算不經過任何模型。

架構層面的敘述（為什麼這樣分層、確定性與適應性怎麼權衡）在
`ARCHITECTURE.md`。被問到設計理念就講那一份。

## 兩條路徑

命題文件的題目是「AI 輔助不動產估價案件審查」，預期成果第一條寫
「透過 AI 輔助完成估價書填寫流程」。所以審查與填寫兩件事都在題目裡，
我們兩條都做了。

**審查模式**吃已填好的書表 PDF，逐格比對並指出填錯的地方，還會算出
那個錯誤讓每平方米的補償價差多少。用的是官方查估書表範本那個金山商業用地案，
那是唯一有官方答案可以對的案子。

**產出模式**吃填好的地價區段勘查表，算出區域因素明細表與比較法調查估價表
該填的每一格，產出可交件的檔案。對應正式題目的樹林區普通住宅用地案，
那個案子的兩張表是空白待填的。

兩條路徑共用 `kernel/` 的判級與矩陣查表，換行政區是換一份規則集 JSON
而不是改程式碼。

## 三個特色

### 一、規則不是人抄的，是跟官方基準表逐格機器對照過的

樹林區普通住宅用地有 29 個區域因素細項，每個細項有一張 5×5 修正率矩陣
與五段等級門檻。這些數字如果抄錯一個，整條計算鏈不會有任何異狀：
判級照樣成功、小計照樣加得起來、自我驗證照樣通過。錯的答案會安靜地
一路走到交件的書表上。

處置方式是反過來驗來源。從官方評價基準明細表 PDF 把矩陣與門檻抽出來，
跟規則集 JSON 逐格比對，兩邊都是機器讀的，不經過人的眼睛。

**另外一層是合規性。** 查估辦法第 20 條第 2 項規定自訂的修正幅度不得逾越
內政部訂定的最大影響範圍。那份上限表也編進來了（住宅用地與商業用地各分
四級），樹林這組 28 個細項全數在「普通住宅用地」欄的上限內，零超標。
「其他影響因素」在基準表上是空白格，未訂上限，所以回報 INFO 而不是警告。

```bash
python -m pytest kernel/tests/test_ruleset_matches_official_pdf.py -v
```

驗到的東西：28 個矩陣逐格一致（29 個細項扣掉都市計畫那個格式特殊的，
它單獨驗）、每個矩陣是方陣且對角線為 0 且上下三角互為相反數、
18 個數值門檻型細項的 144 個門檻值一致、11 個類別型細項的每個等級
都有寫法對得回基準表、每個細項都記來源頁碼。

144 個門檻只有兩組表示法差異，都寫在測試裡並註明理由：
基準表寫中文「四項以上」而規則集記數字 4；傾斜度的基準表是數值區間
而規則集比對整串文字，因為勘查表填的就是「平均坡度未滿5度」那串字。

**可以強調的**：這組測試做過突變驗證。故意把主要道路寬度的 step 從 3.75
改成 3.0、把建蔽率門檻 80 改成 75、把「大部分規劃及闢建」改成
「大部分已開闢」，三種都會紅並指出是哪一個。測試會失敗才算會守。

### 二、每一格都指得回來源，而且敘述不經過模型

表5-1 的 116 格優劣等級與 87 格修正百分比，每一格都帶著四樣東西：
現地量測值、判到第幾級、判級的依據、在評價基準明細表第幾頁。
矩陣查表的結果也記下來（比準地第幾級對比較標的第幾級查到多少）。

產出的檔案裡附一張「計算依據」工作表，14 個欄位、114 列資料
（87 個細項 × 3 個比較標的的明細，加 24 個群組小計與 3 個總修正數）。
最上面直接寫明每一列都由規則引擎產生，敘述不經過任何模型。

前端畫面上每一列都能點開看判級理由與矩陣查表。

**為什麼不用模型寫敘述**：徵收案會被訴願。同一個案子問兩次要得到一樣的答案，
而且要說得出每個數字的法源。規則式產生的敘述同輸入同輸出。
模型潤飾可以加在這之上,不能取代它。

現場可以打開表5-1 的計算依據工作表，指其中一列念出來，例如主要道路寬度那列：
比準地量到 28 公尺判第 1 級優，比較標的量到 7 公尺判第 5 級劣，
查基準表第 2 頁的矩陣得 +15.00%。

**活版的公式是拿真實試算表引擎驗過的**。`openpyxl` 寫入公式後檔案裡不留
計算結果，所以「Excel 打開會算出什麼」要另外驗。做法是讓 LibreOffice 重算
一次再讀回來，24 格群組小計、3 格總修正數與表4 的 10 個計算欄，
真實引擎算出來的值與定版完全一致，而且沒有任何一格是 `#VALUE!` 這類錯誤。

```bash
python -m pytest xlsxform/tests/test_libreoffice_recalc.py -v
```

這組也做過突變驗證：把 `SUMPRODUCT` 的範圍改成印了單位「M」的欄位，
測試會抓到 `G30 重算後是字串 '#VALUE!'`。

### 三、每次產出都自我驗證，而且交出去的檔案有兩份

十項驗證的做法是把活版 Excel 公式描述的關係，套在定版的數值上重算一次比對。
群組小計是不是等於各細項相加、總修正數是不是等於八個群組小計相加、
表4 的絕對值加總與試算價格是不是符合公式關係、比準地比較價格是不是等於
試算價格的加權平均。任一項不通過，CLI 直接回非零而不會產出檔案。

輸出七個檔案，含一份給收件人看的交付說明。表5-1 與表4 各有活版與定版兩份。活版的加總與四則運算是
Excel 公式，局處把表4 的個別因素填進去之後下游會自動更新。定版全部是
算好的數值，用於對照與轉 PDF。

**為什麼要兩份**：`openpyxl` 寫入公式後檔案裡不會有快取值，用程式讀回來
拿到的是公式字串而不是數字。所以驗證要對定版做，交付可用性要靠活版。

## 刻意不做的事（這本身是特色）

計算不交給模型。判級、查表、加總、加權、進位全部在規則引擎裡。
模型算數字沒辦法追溯，徵收案追溯不了就不能用。

不宣稱準確率。這是規則引擎不是預測模型，會被問到就這樣答。
規則對不對可以驗（見特色一），但「準確率 95%」那種說法在這裡沒有意義。

只用官方範本示範。示範資料就是題目給的樹林案與官方空白範本，
沒有自己編的假資料。

表4 的個別因素（項目 7 到 25）留空。題目未提供宗地個別條件資料，
而表4 註記載明那一段由地價查估單位依查估辦法第 20 條辦理。
所以試算價格與比準地地價都是「個別因素以 0 計」的結果,
這個前提寫在表4 的全案備註欄裡。這是資料邊界不是功能缺口。

### 開場（30 秒）

講問題：政府徵收土地要照市價賠償，金額由估價師填在三張官方書表上，
審查人員必須拿著評價基準明細表逐格核對，一個案子上百格，
而錯一格會沿著計算鏈一路影響到最終的補償金額。

講我們做的事：同一個規則引擎，兩個方向。檢查填好的書表哪裡填錯，
以及從勘查表算出書表該填什麼。

### 審查模式（90 秒，戲劇性最強）

```bash
python scripts/demo-review.py
```

第一段官方範本原封不動送審，查 77 格、0 處不符。
講「這是估價師填對的案子，77 格全對」。

第二段改壞兩格。一格把優劣等級填錯，一格把「面前道路寬度」的 +5% 抄成 0
並讓合計與試算價格一路錯下去。系統抓出四處不符，每處指出書表填什麼、
依基準表應為什麼、依據哪一頁。最後一行是重點：

```
價格影響：書表 203,536，依基準表重算 212,958，每平方米差 +9,422 元
```

講「這一格抄錯，每平方米差 9,422 元。徵收案的面積動輒上百平方米」。

改兩格抓到四處要順帶解釋，那不是重複計算。一個等級填錯會同時違反表1 內部的
一致性與表1 對表5-2 的一致性（審查重點第 vi 項），錯誤沿鏈擴散，
那正是人工核對最容易漏的地方。

第三段換一組規則集，結果就變。講「規則是資料不是程式碼，換行政區換一份 JSON」。

比準地量到 28 公尺判第 1 級優，比較標的量到 7 公尺判第 5 級劣，

辨識結果必須先攤給人確認再進計算。

## 預備問答

### 關於填表

**表3 為什麼要填優劣等級？那不是表5-1 的事嗎？**
勘查表本身就有等級欄，在每個細項名稱左邊的兩個窄欄（等級與總級數）。
新北市手冊第 3 章第 25 頁的填載範例是「1 2 都市計畫(內外) 內」這種格式。
而第 5 章第 42 頁要求表5-1 的等級「應與地價區段勘查表內所調查之基本資料及
優劣等級相符」，所以兩張表的等級同源。我們兩邊都填，並有測試逐格核對一致。

**等級文字欄為什麼填「都市計畫內」而不是「優」？**
三份官方文件在這一項不一致。新北市手冊第 52 頁商業範例填「1 內」「1 商業區」，
第 56 頁其他用地範例填「1 內」「4 溝渠用地」，而內政部的查估書表範本填「1 優」。
新北市那兩個範例一致的是都市計畫與使用分區填量測值、其餘填優劣文字，
本案是新北市案件所以從新北市手冊。填量測值還直接滿足「表5-1 應與勘查表相符」。
完整對照表在 `docs/FILLING-BASIS.md` 第五節。

**圈選類設施為什麼有些填「無」有些留空？**
新北市手冊第 3 章第 18 頁：「如無該設施請空白或填載『無』，勿自行修改表單。」
兩者都合規。有「名稱：」欄的我們填「無」（19 格），跟隨手冊第 19 頁範例的做法，
因為填了才分得出「已勘查確認沒有」與「漏填」。
大型車站、學校、市場、公園沒有名稱欄，只有圈選與距離欄，所以留空。

**表4 的個別因素為什麼空著？**
表4 註記自己寫明那 19 個項目由地價查估單位依查估辦法第 20 條辦理，
而題目未提供宗地個別條件資料（面積、寬深度、形狀那些）。
合計欄填 0 並在全案備註寫明「本次計算以 0% 計」，是為了讓試算價格算得出來。
局處填入之後，活版的 Excel 公式會自動把下游更新，權重排序也可能改變。

**容積率為什麼用 200% 而勘查表寫 260%？**
手冊裡沒有「道路未達八公尺則容積率以 200% 計」這條規則，那是地價查估單位的
個案說明。合法性依據是新北市手冊第 42 頁「如因情況特殊，得於備註欄敘明理由後，
酌予調整」。處置是勘查表忠實記載法定容積率 260%，計算用 200%，
差異寫在表5-1 全案備註與計算依據工作表。四個區段同級所以修正率 0.00%，
而且容積率本來就不計入區域因素小計。

### 關於正確性

**你們怎麼知道算得對？**
三層。規則集的 29 個細項矩陣與 144 個門檻跟官方評價基準明細表 PDF 逐格機器
比對，可以現場跑。計算引擎拿官方已填好的金山商業用地案能逐格重現答案。
回填完整性有座標清單釘住並禁止覆寫標籤。三層都做過突變驗證，
故意改壞會紅而不是靜默通過。

**修正率有沒有超過內政部規定的上限？**
沒有。查估辦法第 20 條第 2 項要求不得逾越內政部訂定的最大影響範圍，
那份表在新北市手冊第 46 頁。本案用「普通住宅用地」欄，28 項零超標。
最接近的是有無禁止建築與有無限制建築，自訂 50% 對上限 50% 正好貼齊。

**權重 50/30/20 是你們定的嗎？**
不是，內政部手冊第 53 頁第十一項明文寫「如有 3 件實例，調整百分率絕對值加總
分別為 7%、10%、15%，則價格形成因素之相近程度分別填寫較高、普通、較低，
賦予權重 50%、30%、20%」。絕對值加總的定義也在同一頁第十項。

**準確率多少？**
不宣稱準確率。這是規則引擎不是預測模型，同一份輸入永遠得到同一份結果。
能驗的是規則本身與官方基準表逐格一致，那有測試。

### 關於架構

**換一個行政區要多久？**
編一份規則集 JSON，不改程式碼。目前有三份（金山商業的區域與個別因素、
樹林住宅的區域因素）。`demo-review.py` 第三段就是現場換規則集，結果跟著變。

**AI 在哪裡？**
目前為零，刻意的。計算交給模型就追溯不了，而徵收案會被訴願，
同一個案子問兩次必須得到一樣的答案。要加的位置有兩個：把勘查表 PDF 或掃描件
辨識成結構化欄位，以及把規則式敘述潤飾成更好讀的文字。兩者都在規則引擎之外。

**為什麼不接地圖 API 自動算距離？**
評價基準明細表的級距是「區段內有學校或距離未滿 300m」這種法定判準，
而地圖 API 的距離會因路徑演算法與資料更新而變動，今天 280 公尺明天 310 公尺
等級就跳一級，補償金額也跟著變。現在的做法是距離由勘查人員現地量測後填在
勘查表上，系統只負責查表，責任歸屬清楚。

**系統會不會自己改數字？**
不會。系統開放的是判斷，鎖住的是計算。事實類（量測值）可改並留痕跡，
推導類（等級、修正率、小計、試算價格）唯讀，設定類（用地類別、案件例外）
可改但要填理由。容積率那個覆寫就是走 `case_overrides`，原值保留、
理由與來源都記在檔案上。

**有沒有認證？**
沒有，已知，部署前要補。目前任何人都能打那支 API。
