# 需求：回填樹林區普通住宅用地的三份查估書表

> 建立於 2026-09-12。這份 spec 的用途是把範圍與決策固定在檔案裡，不依賴對話記憶。
> 接手時先讀這份，再讀 `design.md`（格位與演算法），最後看 `tasks.md`（進度）。

---

## 1. 要解決的問題

新北市地政局提供樹林區一個徵收案的勘查資料，要求產出填答完成的查估書表。
官方提供的三份 xlsx 範本是空白的，而且沒有任何計算能力（實測三份的 Excel 公式
數量分別是 0、0、1，那唯一的一個是 `=(1)+(2)+(3)+(4)+(5)+(6)+(7)+(8)`，
`(1)` 到 `(8)` 不是儲存格位址，它是印給人看的說明文字）。

換句話說，局處目前是手算的。這正好對應命題文件列的第三個痛點：修正率加總及
跨表抄填（如區域因素總修正數）容易出現計算或填載錯誤。

## 2. 輸入

| 檔案 | 內容 | 用途 |
| --- | --- | --- |
| `正式題目/題目.pdf` | 6 頁：p1–p4 四張已填好的表3、p5 空白表5-1、p6 部分填寫的表4 | 事實來源 |
| `正式題目/評價基準明細表.pdf` | 9 頁：p1–p5 區域因素、p6–p9 個別因素 | 級距與修正矩陣，已編成規則集 |
| `正式題目/表3地價區段勘查表.xlsx 的副本.xlsx` | 空白範本，可見工作表「表3區段勘查表」 | 回填目標 |
| `正式題目/表4比較法調查估價表.xlsx 的副本.xlsx` | 空白範本，可見工作表「表4比較法調查估價表」 | 回填目標 |
| `正式題目/表5影響地價區域因素分析明細表(住宅用地).xlsx 的副本.xlsx` | 空白範本，可見工作表「表5-1區域因素明細表(住)」 | 回填目標 |

三份 xlsx 各自是同一本 24 張表的工作簿，只有一張可見，其餘 23 張是隱藏的舊範本
樣例（內容是 ○○鄉、甲一、乙二 這類佔位資料）。那些隱藏工作表不是本案資料，
不要當成缺漏，也不要動它們。

評價基準明細表的內容已經編成 `kernel/rules/shulin_residential_regional.json`
（29 個細項全數編碼），所以本流程實際讀的是那份規則集而不是 PDF。

## 3. 輸出

**三個 xlsx 檔案**，各自對應一份官方範本，回填後另存。

| 輸出檔 | 來源範本 | 工作表 |
| --- | --- | --- |
| `表3地價區段勘查表-filled.xlsx` | 表3 範本 | 四張：`表3 P001-00` 到 `表3 P004-00` |
| `表5影響地價區域因素分析明細表(住宅用地)-filled.xlsx` | 表5 範本 | 一張：`表5-1區域因素明細表(住)` |
| `表4比較法調查估價表-filled.xlsx` | 表4 範本 | 一張：`表4比較法調查估價表` |

四個區段各一張工作表放在表3 那個檔案裡（決策來自使用者，2026-09-12：
「一個檔案四張表」）。

這個結構有一個技術上的必然性：`openpyxl` 的 `copy_worksheet()` 無法跨工作簿，
所以三份範本不可能在不重建格式的前提下合併成單一檔案。同檔案內複製沒有問題，
實測表3 範本複製後 188 個合併格、20 個欄寬、46 個列高與列印版面設定全部一致。

原範本的空白工作表不保留。做法是先把原工作表複製三份，四張都改名為對應的區段
編號，再各自填入，這樣不會留下一張沒填的表造成交件時的混淆。23 張隱藏工作表
維持不動。

同時產兩個版本，用途不同：

1. **活版**（`*-live.xlsx`）：加總與四則運算寫成 Excel 公式。局處把個別因素填進
   表4 之後，下游的試算價格、絕對值加總、權重、比準地比較價格會自動更新。
2. **定版**（`*-final.xlsx`）：所有格子都是規則引擎算好的數值，個別因素以 0 計
   並在備註欄標明前提。用於對照答案與轉 PDF。

兩份的數字必須一致。這本身就是一道驗證：公式算出來的與引擎算出來的不同，
表示有一邊寫錯了。

## 4. 範圍：哪些格我們算，哪些不算

### 4.1 我們算（完整且可對照）

- 表5-1 一整張：116 格優劣等級（29 細項 × 4 區段）、87 格修正百分比
  （29 細項 × 3 標的）、24 格群組小計（8 群組 × 3 標的）、3 格總修正數
- 表4 的區域因素調整百分率 3 格（`J8`、`N8`、`R8`）
- 表3 四張的勘查值（那是把題目 PDF 的內容重現到 xlsx，屬於抄寫不是計算）

### 4.2 我們不算（沒有輸入資料）

表4 的個別因素項目 7 到 25 共 19 項。理由有兩層：

1. 表4 自己的註記寫「由地價查估單位依『土地徵收補償市價查估辦法』第20條及
   『影響地價個別因素評價基準表』考慮個別因素調整項目中1~5修正細項」。那個
   「1~5」是表4 左側的五個群組（宗地條件、道路條件、接近條件、周邊環境條件、
   行政條件），剛好涵蓋項目 7 到 25 全部。
2. 更根本的原因是題目沒給輸入。實測題目第 6 頁的表4，項目 7 面積、8 寬度、
   9 深度到 25 有無禁限建全部空白，只有單位標記 M。題目全 6 頁沒有任何一頁
   記載宗地的個別條件。

所以這不是選擇不算，是算不出來。

### 4.3 個別因素空白會連動到哪些格

這幾格在活版寫成公式，在定版以個別因素 0 計並標註前提：

- 表4 `R29` 合計（個別因素合計）
- 表4 `R30` 調整百分率絕對值加總
- 表4 `R31` 試算價格與比較標的權重
- 表4 `R32` 比準地比較價格

其中權重要特別注意：權重是依「調整百分率絕對值加總」由小到大決定的
（3 件時較高 50%、普通 30%、較低 20%），個別因素填入後那三個數字會變，
排序可能整個改變。目前只算區域因素的話是：

```
標的1  23.50%  → 最大 → 權重 20%
標的2  19.75%  ┐ 兩者打平，作業手冊沒有規定打平怎麼處理
標的3  19.75%  ┘
```

所以定版的權重是暫定值，這一點必須在備註欄寫清楚。

### 4.4 表5-1 有三項不調整

表5-1 備註欄載明「使用分區、建蔽率、容積率修正併同於比較法調查估價表宗地個別
因素考量調整修正」。所以這三項的優劣等級照填（116 格都要填，不能留空），
但不計入群組小計與總修正數：

- `regional.land_control.zoning`（使用分區）
- `regional.land_control.building_coverage`（建蔽率）
- `regional.land_control.floor_area_ratio`（容積率）

### 4.5 其他影響因素(8) 題目已給答案

題目第 5 頁的表5-1 在這一列已經預填「- 無」與 0.00，等級欄是「-」而不是 1 到 7
的級數。所以本案這一項不參與計算，性質與 4.4 那三項相同。規則集裡仍完整編碼
（基準表確實有七級矩陣），但填表時照題目填「-」與「無」。

## 5. 驗收標準

### 5.1 必須重現的已驗證數字

```
                總修正數      調整至基準日單價 × (1+總修正數) = 試算價格
標的1 P002-00   +23.50%       137,925 × 1.2350 = 170,337 元/㎡
標的2 P003-00   +14.75%       140,808 × 1.1475 = 161,577 元/㎡
標的3 P004-00   +14.75%       180,292 × 1.1475 = 206,885 元/㎡
```

八個群組裡只有交通運輸(2) 非零，其餘七組四個區段等級相同所以修正率為 0。

### 5.2 格數必須對得上

| 項目 | 格數 |
| --- | --- |
| 優劣等級 | 29 細項 × 4 區段 = 116 |
| 修正百分比 | 29 細項 × 3 標的 = 87 |
| 群組小計 | 8 群組 × 3 標的 = 24 |
| 總修正數 | 3 |

116 格等級全部要判得出來，不能有任何一格因為級距缺口而拋錯。其中 26 個細項
四個區段等級相同（修正率必為 0），但等級欄一律要填。

### 5.3 其他驗收條件

1. 活版與定版的數字一致。
2. 原範本的版面、格式、隱藏工作表不被破壞。
3. 每一格算出來的等級與修正率都能講出依據（落在基準表哪一級、查矩陣哪一格）。
4. 完整測試維持 180 passed 以上。
5. 一行指令可以重跑整條鏈，不需要人工介入。

## 6. 刻意不做的事

1. **不寫表3 的 PDF parser。** 表3 是雙欄版面、四張、22 欄、188 個合併格，
   而且欄位比表5-1 需要的多出十幾項（接近聚落程度、風勢、土質、農地改良、
   整組工商活動等）。現有 `parser/table1.py` 的座標索引是對金山的表1 量出來的，
   全部要重測，是目前風險最高的一塊。改以人工核對的事實 JSON 作為輸入，
   那份 JSON 之後可以當 parser 的驗收標準（parser 要能產出一模一樣的 JSON）。
2. **不實作土地開發分析法。** 個別因素基準表的容積率那一項沒有矩陣，寫的是
   「容積率差異以土地開發分析法進行試算調整」。地政局口頭指示本案容積率一律
   以 200% 計算（理由是四個區段道路均未達八米），四個同值所以修正率為 0，
   正好繞過這個引擎處理不了的型態。
3. **不做 xlsx 轉 PDF 的自動化（暫定）。** 本機沒有任何轉檔工具（LibreOffice、
   Excel、Numbers、pandoc、weasyprint、wkhtmltopdf 全部沒有）。先把 xlsx 產對，
   再決定是用 `reportlab` 自己畫版面，或在有 Excel 的地方另存。
4. **不改 `requirements.txt`。** 那份記錄的是 Python 3.13 環境的正確版本。
   本機是 3.9.6，實際裝的是相容版本，差異記在 `steering/tech.md`。

## 7. 局處口頭補充的兩條規則

書面資料沒有，照書面算會錯。

1. **容積率一律用 200%。** 原話是「比較標的跟比準地的道路如果沒有到達八米，
   容積就不能到達 200 以上。這個專案內都是八米內，所以容積一律使用 200 計算」。
   表3 原填 P001 260%、P002 200%、P003 260%、P004 260%，全部改用 200%，
   四個同值所以修正率為 0。而且容積率本來就移到表4（見 4.4）。
2. **捷運開發區用住宅區算。** 比準地 P001-00 的區段範圍寫「捷運開發區(變更前為
   第一種住宅區)」，使用分區要當第一種住宅區，不是捷運用地。基準表裡兩者差一級
   （捷運用地(聯開) 是優、住宅區是稍優）。對表5-1 沒影響（使用分區已移到表4），
   但表4 項目 22 要填「第一種住宅區」。

## 8. 不可跨越的界線

1. **判斷交給規則引擎，運算才寫成公式。** 等級判定與修正率查表只能由
   `kernel/` 做，因為那要翻評價基準明細表的級距與 5×5 矩陣並附依據。
   加總、乘法、加權這類機械運算可以寫成 Excel 公式。
2. **`api/` 不做計算。** 產出表5-1 全部格子的函式加在 `kernel/src/compute.py`，
   不放 `api/review.py`。一旦 api 自己算，追溯鏈就斷在那層。
3. **新模組不 import `kernel/`。** 比照 `pdfform/` 的既有慣例，計算函式由
   呼叫端以參數注入。
4. **不宣稱準確率。** 有官方標準答案的資料只有金山那一份，n=1。
