## 六個關鍵設計決定（都有官方出處）

**1. 同名欄位不共用規則。** `建蔽率 70%` 區域判「優」（60%以上）、個別判「稍優」（70–80%）；`容積率 240%` 同理。所以 factor_id 一律 namespace：`regional.*` / `individual.*`，且 grade 不附著在 fact 上，只能由 `classify(factor, value)` 產生。`test_classify.py` 用 4 個測試把這件事鎖死。

**2. 全程不取整，只在最終取整。** 表4 顯示的「調整至估價基準日單價 188,459」是**顯示欄位**，不參與計算。
```
用顯示值：188,459 × 1.13          = 212,958.67 → 212,959  ✗ 差 1 元
用原值：  184,763 × 1.02 × 1.13   = 212,957.83 → 212,958  ✓ 官方值
```
`test_must_not_round_intermediate_values` 把這個陷阱寫成測試。

**3. 尾數兩套規則，不能混用。**
- 表4 比準地比較價格 → **四捨五入**至個位數（作業手冊 p.53）
- 表14 比準地地價 / 表6 宗地市價 → **分段無條件進位**（查估辦法第21條：逾10萬→千位）

**4. 小計／合計是直接相加，不是連乘。** 佐證：作業手冊 p.96 表5-1 範例 `0+(-36.16)+12.50+(-5.00)+2.25+13.75+10.00+(-2.50) = -5.16`。

**5. 矩陣方向寫在參數名稱上。** `lookup(factor, benchmark_grade, comparable_grade)`，不用 `matrix[a][b]`。基準表版面是「宗地(比準地)」為列、「比準地(比較標的)」為欄。Golden Case 反證：道路種類 優/稍優 → +2.00%。`test_direction_matters_swapping_flips_sign` 防寫反。

**6. validator 只警告、不自動修正。** 見下。

## 已驗證的合規缺口

**金山區商業用地個別因素「道路種類」最大修正幅度 8%，超出內政部上限 5%。**

- 評價基準明細表範例 p.7：矩陣 `0 / 2.00 / 4.00 / 6.00 / 8.00`，黃底最大值 **8**
- 作業手冊附件25（印刷頁154 / PDF頁158）「13.道路種類」商業用地 **5**（兩次獨立抽取一致）
- 法源：查估辦法第20條第2項、作業手冊 p.52（八）1.「應於內政部所訂最大影響範圍內」

**不自動夾到 5%**，因為 Golden Case 的 +2.00% 正是用 step=2.0（即 max 8）算出來的，自動修正會導致無法重現官方答案。合規問題應回報地政局，不是偷偷改數字。其餘 18 項全部合規。

## 分級器支援的型別

| type | direction | 用在 |
|---|---|---|
| `numeric_bands` | `higher_is_better` | 面積、寬度、面前道路寬度、建蔽率、容積率 |
| `numeric_bands` | `nearer_is_better` | 接近學校/市場/公園/車站/商圈 |
| `numeric_bands` | `farther_is_better` | 嫌惡設施（方向相反） |
| `numeric_bands` | `optimal_interval` | 深度（40–100m 最優；未滿10m **或** 100m以上皆為劣，**非單調**） |
| `ordered_category` | `match: exact` | 形狀、臨路情形、地勢、道路種類、停車、禁限建 |
| `ordered_category` | `match: contains` | 使用分區（實填「第二種商業區」須對上「商業區」） |

級距語意：**min 含、max 不含**。`absent: true` 表示條文含「或無」。
`aggregation: worst` 表示多設施取最劣（作業手冊 p.24「以對當地地價影響最大者填寫」）。

⚠️ 停車方便性**必須** exact 比對：「可路邊停車」是「不可路邊停車」的子字串，contains 會把「不可」誤判成「優」。

## validator 檢查項

ERROR（引擎不可用）：級距缺口 / 重疊 / min≥max、未涵蓋 ±∞、等級不連續、矩陣維度不符、對角線非 0、非反對稱、`max_range ≠ 矩陣[優][劣]`、單位不在白名單。

WARN（可跑但需人工確認）：超出內政部上限、內政部規定「不予考慮調整」但自訂表仍訂了值、上限表查無此細項。

`max_range ≠ 矩陣[優][劣]` 這條特別有用：`max_range` 是 PDF 上**另外獨立印出**的黃底數字，可以交叉驗證 step 有沒有抄錯，等於用兩個來源互相校驗 19 個矩陣。

## 待確認事項（UNKNOWN）

1. **「無」的處理**：市場、公園、觀光遊憩、百貨、金融、娛樂、展示中心、嫌惡設施的條文**明文寫了「或無」**；但交流道、廢棄物處理、環境污染**沒寫**，Golden Case 卻分別填了劣、優、優。這三項目前依 Golden Case 反推，需向地政局確認。（本引擎遇到沒有「或無」條文的缺值會**明確報錯**，不會猜。）
2. **絕對值加總的算法**：`|日期| + |區域| + Σ|各項|` 與 `|日期| + |區域| + |合計|` 在本案同為 15.00%，無法區辨。已實作前者（手冊 p.53「各項…先取絕對值後加總」）。
3. **多比較標的時的加權基礎**：以「取整後的試算價格」或「未取整原值」加權，本案 1 件 100% 無法區辨。已實作前者（與表4 顯示一致）。
4. **交易日期調整率的取整**：`184,763 × 1.02 = 188,458.26`，表上顯示 188,459（進位），無明文規定。不影響最終結果（該欄不參與計算）。
